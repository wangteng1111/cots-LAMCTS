已实现 QfilmRW 0.1 的真实光线追迹、参考球面补偿、角频率复场重构、固定采样 CZT、复 OTF、RS1 抽查、误差账本，以及 CPU/双 GPU 测试程序。通用补偿 ASM、beamlet 和矢量分支尚未实现；当前仍是实验版。

最终工作站代码：`785bd687cf1117adbc68312ce8ccbb3ff0479c96`。本地 CPU 矩阵固定于 `fe259d1b52f74c73d75e8b7f0f861dee0e9827aa`；随后新增了奇异线折叠拒绝和解算计划实现哈希，这两项分别通过回归/一致性检查，硬件完整矩阵固定使用最终代码。

## EF40/550 nm 进一步 CPU 验证

在更高的 128→256→512 瞳面采样下，瞳面复 OTF 差 0.000712689、相对积分差 0.00174371，均通过原有门限。角网格加密复 OTF 差 0.000354306、扩大至 0.96 mm 窗口差 0.000345176，均通过。稀疏同边界 RS1 复场相对 L2 差 0.000866458。

本地使用较低的 100M 工作集元素上限，最终状态为 RESOURCE_LIMIT，未完成 0.125 µm 和联合加密。不能算作完整收敛；工作站默认上限为 300M，仍须实际验证。该记录保存在 `artifacts/qfilmrw_ef40_cpu_partial_verify_20261030.json`。

## 工作站：待激活和领取

已向 125 个旧 Qfilm 请求提交 stop/cancel；先前 QfilmRW -01 请求也已取消，以避免重复执行。唯一有效新请求为：

`000-000-020-qfilmrw-real11-cpu-dualgpu-20261030-02`

它固定最终代码，同时运行 CPU、CUDA:0、CUDA:1 三条任务通道，共 231 个 CPU 和 231 个 GPU 工况，并保存原始 PSF、校验和及独立验收记录。任务领取前必须确认旧计算退出；没有借用旧 PSF 或旧 J 作为新结果。

最后一次读取到的上线记录仍是 Bridge 0.6.0，新的任务 claim 尚不存在。**尚不能确认旧工作站任务已停止，也不能声称工作站 QfilmRW 已开始测试。** 当前没有可用的远程命令通道，旧 Bridge 的接管进程门控又阻止了远程部署任务，需要工作站执行一次以下已锁定源码和 SHA256 的激活命令：

```bash
curl -fL --retry 3 https://raw.githubusercontent.com/wangteng1111/cots-LAMCTS/951ec23ac1b4f7aa66a40e7c1672ac2934ff79fe/scripts/bootstrap_bridge_qfilmrw_host.sh -o /tmp/bootstrap_bridge_qfilmrw_host.sh &&
sudo bash /tmp/bootstrap_bridge_qfilmrw_host.sh
```

激活后 Bridge 0.6.1 按 PID/start_ticks/命令行核验停止旧任务，并只领取 QfilmRW 队列。必须等到新的心跳、进程清单、claim 和原生终态才能确认执行/验收。

本地紧凑证据保存在 `artifacts/qfilmrw_real11_cpu_survey_20261030/`。归档可用 Python `gzip.decompress(base64.b64decode(path.read_bytes()))` 解码；清单保存编码文件与解码 JSON 的 SHA256。归档省略原始投影数组，保留原生终态 SHA256，并明确不作为完整验收记录。完整工作站记录使用原始数组及投影复算。
