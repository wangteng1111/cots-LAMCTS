## 连接恢复所需的本机检查

目前配置的访问方式是工作站主动轮询 GitHub 的 Bridge，没有可用的独立 SSH 或远程重启通道。通过同一队列发送任务不能保证唤醒一个已停止或阻塞的轮询服务。

先在工作站本机执行只读检查：

```bash
systemctl status cots-lamcts-bridge.service --no-pager -l
journalctl -u cots-lamcts-bridge.service -n 60 --no-pager
```

若服务为 inactive/failed，可由本机管理员执行：

```bash
sudo systemctl restart cots-lamcts-bridge.service
```

若服务仍 active，先检查日志和现有计算进程，再决定是否重启。服务恢复后，应以新任务的挑战码、实际主机名、代码 SHA 和执行时间作为恢复证据；旧 heartbeat 的 GPU 利用率不能作为当前状态。
